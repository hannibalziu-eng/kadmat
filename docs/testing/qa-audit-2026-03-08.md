## Findings

### P2 - Browser E2E coverage is still shallow on full UI flows
Playwright final matrix:
- 15 passed
- 64 skipped
- no final hard failures

Matrix:
- `/Users/wew/Desktop/kadmat/output/playwright/coverage-matrix.md`
- `/Users/wew/Desktop/kadmat/output/playwright/results.json`

Pattern:
- Guard, API-backed, and lightweight performance checks pass.
- Most richer UI tests are skipped due current Flutter Web accessibility/semantics limitations and capability gating.

Impact:
- The app is not untested, but it is still under-covered at the browser interaction layer.
- We have more confidence in logic and contracts than in full UI automation depth.

Recommended fix:
- Add stronger semantics/test hooks for the key Flutter Web screens.
- Reduce `skip` gating in auth/navigation/customer/technician flows.

### P3 - Mobile WebKit performance is borderline on first hit
Playwright recorded one flaky-first-run in:
- `/Users/wew/Desktop/kadmat/e2e/playwright/tests/performance.spec.ts`

Observed:
- `my-jobs` API took 9242 ms on first run in `mobile-webkit`
- retry passed in 3.3 s

Impact:
- Not a blocking regression, but a real latency warning under mobile-webkit conditions.

Recommended fix:
- Monitor `my-jobs` latency and warm-cache behavior.
- If reproducible, profile backend query path or reduce cold-start overhead in the route.

### P3 - Widget tests emit heavy `ResponsiveProvider not initialized` warnings
Flutter tests passed, but logs are noisy with repeated fallback warnings.

Impact:
- Test output is harder to read.
- Real failures can be buried under non-actionable noise.

Recommended fix:
- Add a shared widget-test bootstrap that initializes the responsive layer once.

### P3 - Snapshot flow still records one browser console resource error
The end-to-end snapshot harness passed, but the final report still recorded:
- `Failed to load resource: net::ERR_CONNECTION_CLOSED`

Artifact:
- `/Users/wew/Desktop/kadmat/output/playwright/snapshot-flow-1773002799943/report.json`

Impact:
- Not a flow blocker.
- Still worth tracing to ensure no asset or background request is being dropped unexpectedly.

Recommended fix:
- Inspect the network requests around the snapshot run and identify which resource closed early.
